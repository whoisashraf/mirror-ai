# Mirror AI v0.3 — demo-readiness layer

This release turns the v0.2 architecture into a rehearsable merchant demo.

## Shopper fitting room

The try-on route is now a fixed visual workspace. On mobile, the upper portion of the viewport remains the current generated look and the lower portion contains the current-look state plus independently scrolling stylist chat. Desktop remains a two-column fitting room.

The current look is explicit. Adding a recommendation intelligently replaces an existing product when the try-on category is mutually exclusive (for example shoes, bottoms or outerwear) and preserves compatible pieces. Dresses replace top/bottom combinations; adding a top or bottom removes a dress.

Completed generations are kept as an in-session history so a shopper can return to an earlier look without regenerating it.

## Actionable Mirror replies

Chat now sends `currentProductIds` to the server. The server can return validated actions:

- `add_product`
- `replace_product`
- `remove_product`
- `try_complete_look`
- `shop_look`

All product IDs are checked against the active merchant catalogue. Removal/replacement targets must also exist in the current look. The UI always requires a shopper tap before changing the visual state.

## Demo reliability

With `VITE_DEMO_MODE=true`, a prepared full-body demo model is available from the photo uploader. Generations create a deterministic, clearly labelled **DEMO FALLBACK PREVIEW** that keeps the reference image and overlays the current product state. It is intentionally not presented as real AI generation.

A small Demo Tools control can reset the entire local shopper state before each pitch.

## Merchant intelligence

Dashboard analytics now includes aggregated shopper intent themes (pairing, occasion, colour, budget, modesty, etc.) and products generating the most try-on/recommendation engagement. Raw private chat text is not required for these aggregate signals.
